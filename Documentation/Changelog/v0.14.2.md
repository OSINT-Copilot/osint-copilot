A fix for Linux, where the AppImage refused to start on Ubuntu 24.04 and later.

- Fixed the AppImage aborting with "The SUID sandbox helper binary was found, but is not configured correctly". Chromium will not run without a sandbox, and on these systems both of its routes to one are closed: Ubuntu forbids unprivileged user namespaces to unconfined programs, and the setuid helper cannot work from an AppImage, whose contents are mounted `nosuid`. The application now unpacks itself once into `~/.cache/OSINT Copilot/<version>` — an ordinary filesystem, where the sandbox works — and runs from there. The first start prints one line and takes a few seconds; later starts reuse it, and older versions are removed.
- Running the AppImage needs no flags and no environment variables. `--no-sandbox` is deliberately not used: this application renders captured web pages, enricher responses and model output.
- Where unprivileged user namespaces are still allowed, and for the .deb, nothing is copied and the application runs in place. `OC_NO_SELF_INSTALL=1` turns the behaviour off.
