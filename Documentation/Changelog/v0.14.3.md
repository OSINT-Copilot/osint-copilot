The AppImage now says exactly what to do when Ubuntu will not let it set up the Chromium sandbox, instead of aborting with a message from Chromium.

- 0.14.2 tried to solve this by unpacking the application to `~/.cache`. That was the wrong diagnosis: the restriction is on user namespaces, not on where the files sit, so it still aborted with "The SUID sandbox helper binary was found, but is not configured correctly".
- What is true: Ubuntu 24.04 and later deny unprivileged user namespaces to applications that are not installed, and Chromium's other route to a sandbox needs a helper owned by root — which an AppImage cannot carry, because its contents are mounted `nosuid`.
- So the application unpacks itself once to `~/.cache/OSINT Copilot/app`, an ordinary filesystem where a root-owned helper does work, and then prints one command to run:
  `sudo chown root:root "~/.cache/OSINT Copilot/app/chrome-sandbox" && sudo chmod 4755 "…"`. Run it once and every later start has a full sandbox, upgrades included.
- `OC_SANDBOX=off` starts without the sandbox for anyone who prefers that, and the .deb still needs none of this.
